# IDS 批量预览工具

改完 `ids_anal.py` 的算法后，一次性查看它在多个部件组合上的合成效果。

## 启动

**双击 `start.bat`**，或命令行：

```
cd D:\2026harucpp\web\preview
python preview.py
```

浏览器会自动打开（不想自动开就加 `--no-browser`）。
端口默认 18080，被占用时自动往后找，控制台会打印实际地址。

> 服务是**常驻进程**，关掉那个命令行窗口服务就停了。
> 建议自己开个窗口跑着 —— 别依赖别处启动的实例，后台进程可能被回收。

## 用法

左侧输入框，**每行一个 IDS**，点「渲染」。

- **自动** 按钮：开启后输入即刷新（700ms 防抖）
- **实心 / 轮廓**：切换填充模式。轮廓模式便于看笔画走向与接缝
- **网格**：显示 200×200 画布边界 + 十字中线，便于判断左右比例

输入列表存在 localStorage，刷新页面不丢。

## 改算法后怎么生效

**不用重启服务。** 每次请求都会 `importlib.reload(ids_anal)`，
所以改完 `ids_anal.py` 直接点「渲染」就是新算法。

## 链路

```
IDS "⿰忄忽"
  → 解析 (op, [部件...]) → ch_uni() → u5fc4, u5ffd
  → ids_anal.IDS("⿰", [...])           ← 你的算法
  → kage_contour.extract_contours()    ← node 提取带笔宽轮廓
  → contours → 前端画 SVG
```

## 性能做法

`glyph_extend` 有两点很慢，工具在启动时处理掉了：

1. `glyph_extend.get_data` 是**线性扫描 250 万行**（每次查询 0.5~38 秒）
   → 启动时建 `name→data` 索引并替换，降到 **0.065 毫秒**

   **替换时必须精确复刻原版语义**，因为原版用的是子串匹配，不是相等：

   ```python
   if name in targets:      # 子串包含
       data = cols[2].strip()
   ```

   于是查询 `u670b-04` 在该变体不存在时，会命中本体 `u670b` 等更短子串
   —— 这正是**后缀缺失时回退到原字形**的设计。工具的索引版在 `targets`
   的所有子串里取「行号最大」的匹配，与原版逐字一致
   （14 个含缺失变体的用例对照，0 处不一致）。

   ⚠️ 不能用精确匹配 `dict.get(targets)`：那会让所有缺后缀的情况直接返回
   空串，随后 `unfold` 里 `eval("")` 抛 `SyntaxError`，**⿱ 会几乎全灭**
   （因为 -04 变体绝大多数并不存在）。

   另外索引必须**全量**建：字形名首字母不只是 `u`（还有 h/l/s/j/k/d… 约 198 万条），
   只留 `" u"` 会漏掉大半。

2. 轮廓提取每次起一个 subprocess
   → 用 `extract_contours`（支持批量），N 个字形只调一次 node

实测：启动约 1.5 秒，**18 个字形约 360ms**。

## 错误提示

缺后缀会自动回退到原字形（见上），所以那不是错误。
真正会报错的是**该部件连本体都不在库里**，此时会附上它在库中
实际可用的变体，便于判断是换部件还是改后缀：

```
[⿰𠀀木] IDS() 异常: SyntaxError
   该部件在库中的可用变体:
      u20000: 本体=有  变体=-02
      u6728: 本体=有  变体=-01 -02 -03 -04 ...
```

## 已知限制

- 只支持 `ids_anal.IDS` 已实现的操作符（目前是 **⿰ / ⿱**）。
  用 `⿲ ⿳ ⿴…` 会提示「未实现该操作符」
- 不支持嵌套 IDS（`IDS()` 接受的是单字符部件名）
- 部件名由 `ch_uni()` 从字符码点生成，不能直接写字形名
